● Both answers, then the one thing still open.

  "Should I create a soft to generate it?" — No. Don't write a separate program.
  The generator is Nix itself: a module reads the binds attrset, emits an SVG
  string via pkgs.writeText, and the result is a path in the store. No runtime
  dependency, no second language, and it can't drift from your binds because
  it's built from them. Nix string templating is bad at computing layout, but a
  keyboard map doesn't need computed layout — the key geometry is a fixed
  skeleton and Nix only fills in labels per keysym. That's well within what it
  handles cleanly.

  One structural note: right now binds.nix keys on strings like "Mod+Shift+F"
  with the title alongside the action. To feed both niri and the cheatsheet I'd
  want a small shared attrset those two are derived from, rather than
  string-parsing "Mod+Shift+F" back apart. That's a refactor of binds.nix, so it
  goes in the design.

  "How to render it?" — SVG opened in a lightweight Wayland image viewer,
  toggled by a bind. You already have most of this: window-rules.nix:38 has a
  ^Cheatsheet$ rule (floating, 900px, top-left) left over from the fzf/glow
  attempt, and the commented-out Mod+Shift+Slash block has the toggle logic.
  Both get reused. You have no image viewer installed, so it needs one — swayimg
  (Wayland-native, SVG via librsvg, transparency, settable app-id) over imv.
  The alternative is generating HTML and opening it in a browser window; you'd

  for a thing you want to feel instant. I'd take SVG.

  One correction to what I said earlier: I recommended SVG when the plan was a

  rename a bind. This design needs a real layout engine.

  Context I picked up: you have ~46 binds in three comment-sections (Utils /
  Layout Behavior / Apps), which regroup naturally into about six cards —
  Navigation, Windows, Workspaces, Monitors, Layout, Apps. Good fit for the
  reference. You also have no global palette module (catppuccin lives only
  inside nvim), so the accent colors get defined in the cheatsheet module
  itself. If you'd rather hoist a shared palette into base/, say so — I'm not
  folding that in unasked.

  Which layout engine builds the picture?

  - Typst — pkgs.typst, ~30MB, compiles a generated .typ to PNG/SVG at build
    time. Real layout (grid, auto-sizing boxes, rounded rects, gradients, custom
    fonts), fully deterministic, trivial for Nix to emit. Cost: no blur, so the
    neon glow around the cards in your reference becomes a flat accent stroke.
    Everything else reproduces.
  - HTML/CSS → headless Chromium screenshot at build time — exact fidelity to
    the reference, glows included, and CSS is the thing that design was drawn
    in. Cost: Chromium enters your build closure. That's a ~1GB substitution you
    don't currently have, pulled in to render a cheatsheet.
  - HTML/CSS shown live in a browser window — no build-time render, full CSS.
    Cost: a browser starting up every time you hit the key, and Firefox/zen is
    awkward to pin to a specific app-id and floating geometry.

  I recommend Typst. It's the only one that's both light and deterministic, and
  losing the glow is a cosmetic hit on a design that's already carried by the
  accent colors and the keycap chips.

● Both fonts you need are already in modules/features/desktop/fonts.nix —
  FiraCode Nerd Font for the keycaps, Noto Sans for the labels — so typst can be
  pointed at those store paths in the build sandbox with no new dependency.

  Quick orientation since you haven't used it: typst is a markup language that
  compiles to PDF/PNG/SVG, with a real scripting layer. You write #grid(...),
  #box(fill: .., radius: ..), #text(..). It's much closer to writing a document
  than writing SVG, and the layout engine sizes boxes around their content —
  which is exactly the problem we needed solved. Nix's job is only to emit a
  .typ file; typst does the rest.

  Now the design, first section.

  1. Data model

  The blocker is that binds.nix keys on strings like "Mod+Ctrl+Shift+N". The
  cheatsheet needs the modifiers as separate chips, so string-splitting that
  back apart is the wrong direction. Instead, one shared list becomes the source
  for both consumers:

  { mods = [ "Mod" "Shift" ]; key = "F";
    title = "Fullscreen"; category = "windows";
    action.fullscreen-window = [ ]; }

  binds.nix derives the niri attribute name by joining mods ++ [ key ] with +,
  and keeps hotkey-overlay.title from title — so niri's built-in Mod+? keeps
  working unchanged. The cheatsheet reads the same list and gets mods and key
  pre-split for the chips.

  Two things fall out of this:

  - category is new data you'll set per bind. It's what assigns a bind to a
    card, so a new bind appears on the cheatsheet automatically once it's
    tagged. A bind with an unknown category should fail the build rather than
    silently vanish from the sheet.
  - Key display names. BracketLeft → [, Return → RETURN, Escape → ESC. A small
    lookup table in the cheatsheet module, falling through to the raw name.

  # Niri Keybind Cheatsheet

  ## Problem

  Niri's built-in hotkey overlay (`Mod+?`) renders a plain list. It is hard to
  scan
  and gives no visual grouping. An earlier attempt (a commented-out
  `Mod+Shift+Slash`
  bind spawning ghostty + fzf + glow over hand-written markdown files) was
  abandoned;
  it required maintaining a copy of the binds by hand.

  ## Goal

  A graphical cheatsheet generated from the bind definitions themselves, so it
  cannot
  drift, toggled by a keybind.

  ## Non-goals

  - A keyboard-layout map. Rejected in favour of a grouped card grid.
  - A live overlay that queries niri at runtime. The image is built with the
  system.
  - Header and footer branding from the reference design.
  - A modifier legend. Dropped with the header.

  ## Design

  A dark 3x2 grid of category cards. Each card has an accent colour, an icon, a
  title
  and subtitle, then rows of keycap chips against an action label.

  ### Source of truth

  `flake.lib.niri.keybinds`, a function of `{ pkgs, lib }` returning a list of
  records:

      { mods = [ "Mod" "Shift" ]; key = "F";
        title = "Fullscreen"; category = "windows";
        action.fullscreen-window = [ ]; }

  It must be a function rather than plain data because the screenshot bind
  resolves
  `lib.getExe pkgs.grim`. `flake.lib` is typed `lazyAttrsOf raw`, so a function
  is a
  legal value.

  Two consumers:

  - `binds.nix` joins `mods ++ [ key ]` with `+` to form the niri attribute
  name, and
    maps `title` onto `hotkey-overlay.title`. The built-in `Mod+?` overlay keeps
    working unchanged.
  - The cheatsheet reads `mods` and `key` already split, which is what the chips
  need.

  `category` is new per-bind data. An unrecognised category fails the build
  rather
  than dropping the bind silently from the sheet.

  ### Rendering pipeline

  Nix does not generate typst source. Typst's `#` and `$` sigils would need
  escaping
  inside Nix strings, producing an unformattable blob. Instead:

  1. Nix writes `binds.json` — cards, each with label, subtitle, accent, icon,
  and
     rows of `{mods, key, title}`.
  2. `cheatsheet.typ` is a real file in the repo. It does `#let cards =
  json("binds.json")`
     and holds all layout and styling.
  3. A `runCommand` derivation places both in a build directory and runs
     `typst compile --font-path <fira-code-nerd> --font-path <noto-sans>`,
  emitting a PNG
     into the store.

  This keeps the typst file editable and lets the design be iterated standalone
  against a hand-written `binds.json` before it is wired to Nix.

  ### Canvas

  1600x900, exported at 2x. Sized to squid's `eDP-1` (1920x1080 at scale 1.2, so
  1600x900
  logical) — the tightest realistic target. All sponge outputs are roomier.

  ### Cards

  | Card | Binds | Contents |
  |---|---|---|
  | Navigation | 6 | focus column left/right, focus window up/down, overview,
  focus floating/tiling |
  | Windows | 8 | close, fullscreen, expand, float, rotate width, center column,
  consume/expel |
  | Workspaces | 4 | focus workspace up/down, move column to workspace up/down |
  | Monitors | 8 | focus monitor x4, move column to monitor x4 |
  | Apps | 5 | terminal, menu, browser, lock, screenshot |
  | System | 3 | exit niri, switch keyboard layout, cheatsheet toggle |

  `Mod+Shift` move counterparts sit in Navigation beside their focus versions,
  as pairs.

  ### Palette

  Background `#0a0e17`, card `#0f1420`, primary text `#e6edf3`, secondary
  `#8b98a9`.
  Card accents: Navigation `#4a9eff`, Windows `#a855f7`, Workspaces `#22c55e`,
  Monitors `#06b6d4`, Apps `#f59e0b`, System `#f43f5e`. Card borders are the
  accent at
  low alpha. There is no global palette module in this config — catppuccin is
  scoped to
  nvim — so these are defined in the cheatsheet module.

  ### Fonts

  FiraCode Nerd Font for keycaps and card icons, Noto Sans for labels. Both are
  already
  in `modules/features/desktop/fonts.nix`; the derivation points typst at their
  store
  paths. Card icons are Nerd Font glyphs, chosen and confirmed by rendering
  during
  implementation.

  ### Key display names

  A lookup table maps `BracketLeft` to `[`, `Return` to `RETURN`, `Escape` to
  `ESC`,
  falling through to the raw name.

  ### Toggle

  Following the shape of the abandoned `Mod+Shift+Slash` block: query `niri msg
  windows`
  for the cheatsheet app-id; close it if present, otherwise launch
  `swayimg --class=cheatsheet` on the store path. The key toggles rather than
  only opens.
  swayimg is referenced via `lib.getExe` and is not added to `home.packages`,
  keeping the
  feature contained in one directory.

  ## Files

  | File | Change |
  |---|---|
  | `modules/features/desktop/compositor/niri/keybinds.nix` | New. The bind
  list. |
  | `modules/features/desktop/compositor/niri/binds.nix` | Rewritten as a
  derivation of the list; 197 lines to roughly 20. |
  | `modules/features/desktop/compositor/niri/cheatsheet/default.nix` | New.
  Card metadata, key names, JSON writer, typst derivation, toggle script. |
  | `modules/features/desktop/compositor/niri/cheatsheet/cheatsheet.typ` | New.
  Layout and styling. |
  | `modules/features/desktop/compositor/niri/window-rules.nix` | Existing
  `^Cheatsheet$` rule matches swayimg's app-id; width grows from `fixed = 900`.
  |

  ## Verification

  `just ci-light` is the gate; it builds the derivation and catches eval and
  typst
  failures. Visual correctness cannot be automated here — the rendered PNG is
  checked by
  screenshot at each iteration.

  ## Risks

  - Typst has no blur, so the reference's neon glow becomes a flat accent
  stroke.
    Accepted; the design is carried by accent colour and chip shape.
  - Fonts must resolve inside the build sandbox. If `--font-path` misses, typst
  silently
    substitutes a default rather than failing, so the first render is inspected
  for it.
